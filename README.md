# CodeHub

A full-stack developer learning library built with React, Vite, React Router, CSS, Node.js, and Express. Includes 54 curated resources across 16 categories, featured picks, keyword search, combined filters, resource detail pages, favorites, dark/light mode, and a protected local admin editor. No database, API keys, or paid services are needed.

## Setup

Use Node.js 22.12+ (Node 22 LTS recommended) and npm 10+.

```sh
npm install
npm run dev
```

Open http://127.0.0.1:5173. Express listens on http://127.0.0.1:3001. Vite proxies `/api` to Express. Both bind to loopback by default. Stop both using Ctrl+C.

```sh
npm run dev:admin  # explicitly enable local editing, then visit /admin
npm run validate   # validate catalog, unique links, category coverage
npm test           # storage and HTTP API tests using Node's test runner
npm run build      # produce client/dist
npm start          # production-mode, read-only API on loopback
```

`dev:admin` uses POSIX environment variable syntax (macOS/Linux). On Windows PowerShell, run `$env:NODE_ENV="development"; $env:ENABLE_LOCAL_ADMIN="true"; node --watch server/server.js` in one terminal and `npm run dev -w client` in another.

To inspect the production frontend locally, run `npm run build`, keep `npm start` running, and run `npm run preview -w client`. The Vite config also proxies the preview API. `npm start` serves the API only; it does not serve the frontend build. Nothing is deployed or published by these commands.

## Using the library

Search names, descriptions, keywords, and technologies. Combine category, difficulty, type, and free-only filters. Filter state is stored in the URL, so filtered library links can be bookmarked. Switch between grid and list views, or sort by name or difficulty. Open a card title for details or its arrow to visit the source. Bookmark buttons save favorites in this browser's localStorage. Favorites and theme are the only browser-persisted data; resources always come from Express. Favorites are device/browser-specific and do not sync.

## Editing content

- **Resources:** `server/data/resources.json`, or use `/admin` after launching `npm run dev:admin`.
- **Categories:** `server/data/categories.json`; restart Express after changing this file. Each resource's category must match one of these strings exactly. Remove or recategorize resources before deleting a category.
- **Difficulty levels and resource types:** `server/store.js` exports `levels` and `types` shared through `/api/config`.
- **Category icons/colors:** `client/src/components/ResourceCard.jsx` and the sidebar's icon list in `client/src/App.jsx`.
- **Design and breakpoints:** `client/src/styles.css`.

Resource shape:

```json
{
  "id": "unique-stable-id",
  "name": "React Documentation",
  "description": "The official guide to React.",
  "category": "React",
  "level": "Beginner",
  "type": "Documentation",
  "free": true,
  "url": "https://react.dev/learn",
  "keywords": ["react", "components", "javascript"],
  "featured": true
}
```

IDs are generated by the API and remain stable on updates. Mark resources `featured: true` for the homepage; it displays the first three featured entries in catalog order. All seeded learning material can be accessed for free; some publishers also offer paid products. Availability and pricing can change.

Catalog sources include [MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development), [freeCodeCamp](https://www.freecodecamp.org/learn/), [roadmap.sh](https://roadmap.sh/), [React](https://react.dev/learn), [Node.js](https://nodejs.org/en/learn), [Python](https://docs.python.org/3/tutorial/), and [GitHub Skills](https://skills.github.com/). The complete links are in the resource JSON. Validation checks URL syntax and uniqueness; it does not guarantee third-party uptime.

## API

| Method | Endpoint | Behavior |
| --- | --- | --- |
| GET | `/api/resources` | List resources; supports `q`, `category`, `level`, `type`, `free=true` |
| GET | `/api/resources/:id` | Resource details, or 404 |
| GET | `/api/categories` | Category names |
| GET | `/api/config` | Available levels/types and local editing availability |
| POST | `/api/resources` | Create resource; protected |
| PUT | `/api/resources/:id` | Replace resource fields, preserve ID; protected |
| DELETE | `/api/resources/:id` | Delete resource; protected |

POST and PUT require all required fields in the example (except ID and optional keywords/featured). Returns 400 for validation errors, 403 for blocked writes, 404 for missing IDs, 409 for duplicate URLs, 413 for oversized bodies, and 500 for storage failures. Submitted strings have length limits. URLs must be HTTP/HTTPS without embedded credentials. Duplicate comparison normalizes URL host/default port, ignores fragments and a trailing slash. Query strings are retained because they may identify different resources.

## Local admin security and storage limitations

Editing is **off by default**. The server enables it only when `NODE_ENV=development` and `ENABLE_LOCAL_ADMIN=true`. `npm start` always selects production mode. The executable binds to `127.0.0.1`; write routes additionally require a loopback peer, expected localhost Host, allowed local Origin, custom admin header, and no forwarding headers. No cross-origin CORS access is enabled. Vite stays on loopback and rejects arbitrary Host names. These checks reduce accidental exposure, cross-site requests, and DNS rebinding risks.

**This is not authentication.** Another program or user on your computer can make requests with those headers. Use editing only on a trusted local machine. Do not tunnel, publicly bind, or reverse-proxy admin mode. A public write API requires proper authentication, authorization, CSRF protection, and operational controls; this project does not provide those. The UI being locked is informational; enforcement is on the server.

Mutations are serialized within one server process and written to a unique temporary file before an atomic rename. Failed reads or invalid JSON never reset the catalog; errors return a generic message and leave the original file untouched. Keep backups. Run only **one** server process against this JSON file; no multi-process file locking is implemented. Avoid hand-editing the JSON while admin mutations are running. This storage model is for a small local library, not concurrent production editing.

## Structure

```text
client/src/
  components/ResourceCard.jsx
  pages/Library.jsx, Detail.jsx, Admin.jsx
  services/api.js
  App.jsx, main.jsx, styles.css
server/
  data/resources.json, categories.json
  controllers/resourceController.js
  routes/resourceRoutes.js
  app.js, server.js, store.js, validate.js
tests/
  store.test.js, api.test.js
```

The UI uses Lucide icons. Google Fonts improves typography when available; system fallbacks keep it usable offline. No external runtime API is required.
